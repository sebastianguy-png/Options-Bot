## 1. One rule set for everything (the "backtest ≠ live" item is closed)

`options_bot.py` now has a single signal engine — `indicator_frame()` / `ind_at()` /
`evaluate_entry()` for entries, `_price_exit_core()` / `_strategy_exit_check()` for exits — and
**every** consumer runs it: the live scanner, `/api/debug/scan`, the dashboard backtest, the
walk-forward optimizer, calibration, LR, the hold sweep and the signal-log resolver.

- `tests/parity_check.py` replays the ORIGINAL scanner's gate (from git `e5a7d0f`) against the
  engine on the same bars: **38,817 comparisons, 0 mismatches** (99 tickers × 7 bars × every flag,
  count and threshold). Re-run it after any rule change: `py tests/parity_check.py`.
- The backtest walks exits bar by bar with the tracker's own rules in the tracker's own order
  (target → stop → trailing → stagnation → max hold → RSI/BB → expiry), prices the ~30-DTE
  contract with Black-Scholes at HV30×1.15, settles at intrinsic on expiry.
- Per-date market context (VIX regime, term structure, SPY trend, yield curve, Fed windows,
  macro gate) comes from `market_context_history()` — the same series and the same pure rules
  as the live getters, with the same rounding.
- Window parity: live frames are now **2y** (`LIVE_HISTORY_PERIOD`), backtests **3y** with a
  **282-bar warm-up** (`BT_WARMUP_BARS`) so HV rank, IV range, 52-week range and MA200 are full
  on both sides. Entries stop 21 bars before the end of any window — no survivor bias, and a
  training trade can never read validation bars.
- `hold_days` is now a real rule: `HOLD_DAYS` (default 21) is a max-hold exit in the tracker;
  the optimizer's winning `hold_days` is applied to it like the RSI thresholds.

## 2. GARCH is real now

`arch` was never installed, so "GARCH" had always been plain trailing HV. It is installed; the
engine fits GJR-GARCH(1,1,1)-t (GARCH-normal fallback, HV fallback) per bar on a rolling window
(`rolling_garch_forecast`, disk cache `garch_cache.pkl`, loaded at startup, merged on save).
Two testable flags come out: `garch_expand` (forecast > HV30×1.15) and `garch_contract`
(< HV30×0.85), and a `garch_mode` parameter — `off` / `confluence` (+1 bull/bear signal) /
`gate` (buy calls need expansion, sell puts need contraction) — is in the optimizer grid and in
`live_params()`. The signal log records `iv_at_signal` vs `garch_at_signal`, which is the only
place a real IV-vs-forecast edge can ever be measured (no historical IV exists).

## 3. The real edge (walk-forward, 99 focus tickers, 972 combos)

`py tests/run_real_edge.py` → `tests/real_edge_report.json`. Default live rules, hold 21:

| window | trades | win | avg P&L | PF | Sharpe/trade |
|---|---|---|---|---|---|
| train (to 2026-04-22) | 5,432 | 37.5% | −1.4% | 0.91 | −0.03 |
| validation | 2,268 | 40.6% | −0.6% | 0.96 | −0.02 |

GARCH `gate` was the only thing that helped out of sample (val: n=624, win 42%, avg +1.2%,
PF 1.08) and the optimizer's best combo was simply the defaults + `garch_mode=gate`,
`hold_days=14` (val Sharpe 0.025 — statistically nothing). **That run was before the §1 fixes**
(survivor bias and train/val leak both flattered it); the post-fix re-run is in §3a.

Two facts that matter more than any parameter:
- **Average hold is ~2 bars.** Exit mix is ~50% stop-loss, ~22% take-profit, ~15% RSI target.
  With ±15/+30% premium stops on 30-DTE ATM options, a 1–2% stock move the next day settles
  most trades, so the outcome is close to the next day's direction: a coin flip minus spread.
  `hold_days` 7/14/21 produced identical leaderboard rows for that reason.
- Buy puts are ~85% of all trades (`bear_min` 1 with 14 bear terms fires constantly); they are
  the losing leg (PF 0.92). Sell puts are the only leg with PF > 1 but only ~300 trades.

## 4. Autotrader (new) — how to run the bot unattended

Files: `autotrader.py` (the loop), `broker.py` (LocalPaperBroker / AlpacaBroker), the
**🤖 Autotrade** dashboard tab, `/api/autotrade/*`.

- **Default = local paper ledger** (`paper_ledger.json`, $10k, 1% slippage, no account needed).
  Fills come from the scanner's own Yahoo quotes; the tracker threads refresh them.
- **Alpaca**: open a paper account at alpaca.markets, enable options, paste key/secret in the tab
  (stored in `autotrade_config.json`, which is git-ignored), broker=`alpaca`, paper=Yes.
  Real money additionally requires the environment variable `OPTIONS_BOT_ALLOW_LIVE=1`; the tab
  refuses otherwise and the broker class refuses too.
- Cycle (`interval_mins`, default 5): settle open orders → close every auto position whose
  tracker signal fired (same exits as the backtest) → start a scan if results are older than
  `scan_if_stale_hours` → open the best fresh signals that pass score / two-sided quote /
  spread / DTE checks, sized by `max_position_usd` (long) or `max_collateral_usd` (short put),
  within `max_open_positions`, `max_new_per_cycle`, the `daily_loss_cap_usd` and a re-entry
  cooldown. Regular NYSE hours only unless switched off.
- Kill switch: create a file named `STOP_AUTOTRADE` in the bot folder. "Run one cycle now" in
  the tab forces a cycle (works after hours, on paper) — that is how to test it.
- Every decision is in `autotrade_log.json` (and the tab); closed trades land in
  performance.json with `source: autotrade`, so 📊 Performance is the forward test.
- Unattended: `run_bot_headless.bat` (no browser, restarts on exit, console tee'd to
  `logs\bot_<date>.log`); `install_autostart.ps1` (elevated PowerShell) registers a logon task
  that runs it hidden; `uninstall_autostart.ps1` removes it. A second copy exits with code 3
  instead of fighting for port 5000.
- Tests: `py tests/autotrade_dryrun.py` (52 checks: sizing, short-put collateral, exits, expiry
  settlement, cooldown, loss cap, kill switch, pending orders through a broker outage and partial
  fills, manual close, tick rounding, config normalisation, state persistence) and
  `py tests/engine_smoke.py`.
- A second reviewer pass on the autotrader found and I fixed: pending orders were dropped on a
  timeout before the broker confirmed a terminal state (cancel-vs-fill race → possible double
  close); partial fills were discarded; the Alpaca POST was retried without an idempotency key
  (now `client_order_id` + lookup, no blind retry); two paper-ledger instances could overwrite
  each other (broker creation is locked); short-put collateral was never reserved on paper
  (buying power now = cash − strike×100 per short); the Track tab could delete / re-point an
  auto position behind the broker's back (refused with a pointer to the Autotrade tab); state
  is saved after every mutation and reconciled against the broker at start; staleness uses the
  newest of scan / live refresh; cooldown counts trading days; positions are closed the day
  before expiry (assignment risk); limit prices snap to option ticks; `options_buying_power`
  is used on Alpaca.
- Not done: Alpaca was written against its public REST docs but **never exercised against a real
  Alpaca paper account** (no keys). First thing to do with keys: broker=alpaca, "Run one cycle
  now", read the log. Field names `options_buying_power` and the `:by_client_order_id` lookup
  are from the docs, unverified live.

## 5. What the review of the engine found and what changed (commit `9a5e73f`)

## 7a. Morning session: the exit rules are parameters now

Sebastian's call after the discussion: sweep the exits, re-gate buy puts, drop the yield-curve
block on calls. Done:

- `_price_exit_core()` takes an exit-parameter dict (`EXIT_KEYS`: premium stop, profit target,

  rule off. The live tracker passes `live_exit_params()` (the module constants), the backtest

  uses the stock price from the last full check), `put_trend_gate` (`off` / `not_strong_bull` /
  `bear_only`), `yield_block_calls` (the old inverted-curve block on calls; **off by default

- `WFO_PARAM_GRID` (dashboard optimizer) is 1,024 combos of entries + exits.
  `tests/run_exit_sweep.py` is the big staged version: stage A exits × GARCH (1,152), stage B
  entry params × the 3 best exit sets (576), baselines, and a `robust` flag = profit factor > 1
  in BOTH windows with ≥200 / ≥100 trades. `--apply` saves the stage-B winner as
  `wfo_results.json`. Report: `tests/exit_sweep_report.json`.
- Parity test updated to run the legacy semantics (`yield_block_calls=True`, no put gate).

## 7b. Sweep results (99 focus tickers, 3y, split 2026-01-22) — `tests/exit_sweep_report.json`

**The exits were the damage.** Every one of the 27 robust combos (profit factor > 1 in both
windows, ≥200 train / ≥100 validation trades) has the trailing stop OFF, 24/27 have the
stagnation exit OFF, and the premium stop is either OFF or 50% — never the shipped 15% or 30%.
Profit target 100% or none, max hold 10 or 21 days, stock stop irrelevant. All 27 use
`garch_mode=gate` (no garch-off combo even reached the validation round).

Best robust combo — **garch gate, no premium stop, target +100%, no trailing, no stagnation,
max hold 10, no stock stop**:

| window | trades | win | avg P&L | PF | bars held |
|---|---|---|---|---|---|
| train | 1,003 | 47.7% | +4.6% | 1.18 | 6.0 |
| validation | 524 | 46.9% | +2.3% | 1.10 | 5.0 |
| all | 1,583 | 47.1% | +2.9% | 1.12 | 5.6 |

versus the shipped rules: PF 0.94 train / 0.95 validation on 4,500 / 2,800 trades, 1.9 bars.
Exit mix of the winner: RSI target 51%, max hold 38%, +100% target 10%. Per leg it is not
consistent (calls PF 1.78 train / 0.87 val, puts 1.02 / 1.21, sell puts 1.17 / 3.48 on ~30
trades) — the aggregate is modestly positive, the legs swap places between windows.

**Stage B (re-gated entries) is not evidence.** `bear_min 3 + put_trend_gate bear_only` cuts
the sample to ~90 train / ~110 validation trades; train PF 2.45 vs validation 1.07 is a
textbook overfit. The yield-curve toggle made no difference either way. The entry changes
stay available but should not be applied.

**Costs.** +2.3% per trade before the bid/ask spread. Round-trip spread on the sub-$2 options
this bot picks is 5–15% of premium, so after costs the winner is still ≈ breakeven unless the
universe is restricted to tight-spread names. Next engineering step: a spread-cost model and a
liquidity filter in the backtest, then re-sweep.

Nothing has been applied to the live rules yet (`wfo_results.json` still holds the pre-sweep
result); apply the stage-A winner with the optimizer "Apply" or by saving it as
`wfo_results.json`, and remember it removes the premium stop on live trades.

## 7c. Costs: the sweep net of the bid/ask spread (generic spread model)

`_spread_cost_pct()` charges every backtest trade its ticker's measured round-trip spread
(`spread_model.json` from `tests/measure_spreads.py`; half on an expiry settlement); the
`max_spread_pct` rule drops illiquid tickers on both sides (`pick_option` live). Yahoo blanks
option bid/ask outside 09:30–16:00 ET, so the first measurement (06:55 ET) was empty and this
run used the built-in fallback: 16% round trip below $0.50 premium, 10% to $1, 6% to $3, 4% to
$10, 2.5% above — about **5% of premium per trade on average** for this universe. A live
measurement is scheduled for 09:52 ET; `measure_spreads.py` now refuses to overwrite the model
when nothing was measured.

| rule set | window | trades | net avg | gross avg | PF |
|---|---|---|---|---|---|
| shipped | validation | 2,824 | −5.6% | −0.8% | 0.68 |
| best exits (gate, no stop, no target, hold 21) | train | 838 | −0.3% | +4.4% | 0.99 |
| same | validation | 430 | −2.3% | +3.0% | 0.92 |

## 7. Open strategy questions for the discussion

1. The exits, not the entries, dominate: ±15/30% premium stops make every trade a 1–2 day bet.
   Options to test in the engine (all cheap now): wider stops / no stop for defined-risk longs,
   stock-based stops, or hold-to-signal only.
2. Buy puts fire far too often (`bear_min` 1) and lose; buy calls are blocked 2/3 of the time
   by the yield-curve rule. Re-balance the gates or drop a leg.
3. GARCH `gate` is the only out-of-sample positive; worth a dedicated test with more history
   (the 3y frames help) before trusting it.
4. Run the autotrader on paper for a few weeks — the performance tab is the only unbiased
   test of fills, quotes and the intraday stop behaviour the backtest cannot see.
