## 2. Performance changes

- The main scan no longer prefetches info/calendar/option-chain for all ~500 tickers up front.
  The indicator gate runs on the bulk OHLCV download first; network calls happen only for tickers
  that pass (`prefetch_fn`). Focus scan: ~5 s. Market-context caches are warmed once before the pool.
- Iron-condor block only runs on the dedicated condor scan and reuses one chain for all four legs
  (it used to run on every main-scan ticker with 5 extra chain downloads each).
- `_yf_call` releases the rate-limit semaphore while it sleeps; crumb refresh is debounced.
- Prefetch cache stores only the 4 `info` keys the bot reads (file was several MB).
- Price refresh loop groups positions by (ticker, expiry) and now also evaluates
  target/stop/trailing/stagnation every 3 min (stops were only checked every 6 h).
- The auto-rescan loop existed but was never started — it now runs (every `AUTO_RESCAN_HOURS`).

## 3. Backtest / optimizer changes (these change the numbers — on purpose)

- Removed look-ahead: IV per bar is trailing 30-day realised vol ×1.15, not one GARCH fit on the
  whole 2-year series.
- One open position per strategy per ticker (consecutive signal bars no longer stack trades).
- Time-to-expiry uses trading bars/252, strikes snap to listed increments, Sortino fixed,
  WFO train/validation split is by date (not per-ticker row count), `_wfo_sharpe` needs ≥10 trades.
- Saved WFO params are auto-applied on startup only if validation Sharpe > 0; a run that does not
  validate is shown but not saved over the previous file.
- **Result:** focus-list backtest now reads ~38% win rate, +0.5% avg/trade, profit factor 1.06 —
  i.e. roughly breakeven before costs. The old numbers were inflated by the issues above.
  The backtest signal rules still differ from the live scanner (see §5).

## 5. Open strategy items (user asked to discuss — not changed in code)

1. **Backtest ≠ live.** `_bt_signals_fast` uses *RSI AND BB* for oversold, no `oversold` requirement
   on buy calls, `bear_min` default 1, no Donchian/RS/VIX/macro/EMA/gap filters; live uses OR and all
   of them. The optimizer therefore tunes a different strategy than the one traded. Fix = one shared
   signal function used by both.
2. **Signal combinations are not tested.** WFO sweeps thresholds (486 combos); calibration measures
   each flag's win rate *independently*. Nothing measures interactions.
3. **Calibration weights mostly don't reach the scorer** — key names don't match
   (`sig_macd_bull`, `sig_vol_ok`, `sig_mfi_*` produced; `sig_hv_high`, `sig_above_ma50`,
   `sig_rs_strong` read). Only 5 flags are actually calibrated. LR has no class weighting and
   reports train-set accuracy.
4. **Questionable rules:** sell put fires on `(oversold OR macd_bear)` — a bearish trigger for a
   bullish trade; `vol_confirmed` counts as both a bull and a bear signal.
5. **GARCH** is only used for the B-S "vol verdict" and the signal-log simulator; it is not an
   entry/exit input and the backtest can't evaluate it as an edge yet.
6. **Autonomy:** the bot never had a broker connection. Unattended trading needs a broker with an
   API (SoFi has none), a paper-trading mode first, and a watchdog/scheduler.
