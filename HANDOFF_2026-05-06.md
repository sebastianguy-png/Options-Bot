## 3. Critical "Don't Repeat" Lessons

These came up the hard way this session:

### File-write corruption on `options_bot.py`
Writing to this specific file (10k+ lines, lots of unicode like ⚠ ═ → …) intermittently corrupted on disk — produced null-byte padding, truncated mid-function, and silently broke compilation. Symptoms: file appears intact via `Read` tool but bash sees null bytes; `py_compile` fails mid-string-literal.

**Mitigation:** make edits SMALL and check after each one. After ANY edit, immediately `Read` lines 10395+ to confirm the file still ends with `main()`. If it doesn't, restore from git: `git checkout HEAD -- options_bot.py`.

**Suspected root cause:** Windows Defender Controlled Folder Access, OneDrive sync, or some other write interceptor. Sebastian should investigate but hasn't yet. Most likely fix is whitelisting `C:\Users\sebas\Options-Bot` in Defender → Controlled folder access settings.

### "Options-Bot - Copy" duplicate folder
At one point Sebastian had two folders side-by-side: `Options-Bot` and `Options-Bot - Copy`. The bot was running from the Copy while we edited the original — explained why prints didn't appear. **If new prints don't fire after a confirmed restart, check for a duplicate folder before suspecting code.**

### Microsoft Store python.exe stub
On Windows, `where python` may show two paths:
1. `C:\Users\sebas\AppData\Local\Microsoft\WindowsApps\python.exe` ← stub, silently exits
2. `C:\Users\sebas\AppData\Local\Python\bin\python.exe` ← real Python

The stub responds to `python --version` (returns "Python 3.14.4") but silently exits when given a script. Use `py options_bot.py` (the launcher) or full path to bypass.

### Hold Horizon UI stale text
Tracked tab banner says "every 10 minutes." Wrong. Actual: 5 min price refresh + 6 hour full sell-signal check. Cosmetic only — logic is correct. Sebastian noticed this; hasn't been fixed.

## 4. What's In The File Now (Beyond The Original Handoff)

All of these are committed beyond the `bcde823` baseline. Verify with:
```bash
cd C:\Users\sebas\Options-Bot && git log --oneline -10
```

### WFO multi-core (commits `e68216e`, plus subsequent)
- `WFO_CPU_WORKERS = (os.cpu_count() or 8)` constant — uses all 24 logical cores instead of `MAX_WORKERS=8`
- Module-level worker functions: `_wfo_worker_init`, `_wfo_eval_train_proc`, `_wfo_eval_val_proc`
- `_run_wfo_job` rewritten with `ProcessPoolExecutor` (bypasses GIL — true multi-core)
- Single pool spans both training and validation phases (workers stay alive between)
- Workers receive `hist_map`/`split_map`/`precomp_map` once via `initializer`
- Progress tracking moved to main process via `as_completed`
- **Result:** WFO went from 16% CPU (GIL-bound) to 98% CPU (all cores).

### Universe fix
- `get_universe(force_mode=None)` — new optional kwarg
- WFO endpoint now calls `get_universe(force_mode="full")` so "Full S&P 500" actually runs Full S&P 500 (was silently returning Focus List due to global `SCAN_MODE` lookup)

### Hold Horizon Analysis fixes
- **Race condition fix** in `api_hold_sweep` — `_hs_state["running"]=True` set synchronously before spawning the worker thread (was: JS poll arrived before thread started, saw `running=False`, gave up)
- **Missing function fix** — `_get_snp500_tickers()` was undefined, replaced with `get_universe(force_mode="full")`
- **Timezone fix** in `_sweep_one` — `yf.Ticker.history()` returns tz-aware index but `cutoff` was tz-naive, comparison raised TypeError, bare `except` swallowed it, all tickers silently returned `[]`. Now strips tz before comparing.
- **Per-ticker exception logging** — `_sweep_one` now prints `[HoldSweep] TKR skipped: <error>` so silent failures get surfaced.

### Hold Horizon Level 1 — persistence
- `HS_RESULTS_FILE = "hold_horizon_results.json"` constant
- `_save_hs_results()` fires after every successful HH analysis
- `_load_hs_results()` runs on bot startup, restores `_hs_state["results"]` so analyses survive restarts

### Hold Horizon Level 2 — per-position UI hint
- `_hs_targets_for_position(strategy, days_held)` helper looks up HH data for a tracked position. Returns optimal_day, current avg P&L at the nearest checkpoint, win rate, and a short "verdict" string ("Avg gains compound...", "At/past optimal hold day...", "Near peak avg P&L...", etc.)
- `api_tracked_get` now enriches each position with a `hold_horizon` field (only when HH results exist)
- Tracked-tab JS renders a small "📊 Hold Horizon" box under each position's Performance cell

### Hold Horizon — uses live calibration params
- `_run_hold_sweep_job` now reads `scan_state.get("wfo_params", {})` and passes them to `run_backtest_ticker`. Ensures HH tests the SAME setups the live scanner trades, not the loosest possible defaults.
- Prints `[HoldSweep] Using live calibration params: {...}` at start of every run for visibility.

### Hold Horizon — per-strategy trade count column
- HH analysis table now shows a "Trades" column with per-strategy n.
- Color coded: red < 30 (small sample warning), yellow < 100 (modest), gray >= 100 (statistically solid).
- Critical for spotting cases where Sell Put shows "100% win rate" but only fired on 8 trades (Sell Put gated by `price ≤ MAX_PRICE_SELL = $10`, so universe is tiny).

### Scan optimizations
- `SCAN_PREFETCH_WORKERS = 16` — bumps prefetch phase only (kept main scan loop at 8). Modest scan speedup.
- `prefetch_cache.pkl` — disk cache for `tkr.info` and `tkr.calendar` with 24h TTL. Skips ~50% of yfinance round-trips on repeat scans (only saves on info/calendar; option chain always fetched fresh).
- `_save_prefetch_cache()` fires after every prefetch phase
- `_load_prefetch_cache()` on bot startup

## 8. Quick Repro / Smoke Tests

If anything looks wrong on a fresh start:

1. **Bot won't launch:** check Task Manager for orphan `python.exe`, kill them, retry. Then check for `Options-Bot - Copy` duplicate folder.
2. **Scan returns 0 of everything:** likely the applied WFO params are too strict. Run a fresh WFO and apply, OR temporarily skip the Apply step (defaults will produce signals).
3. **HH hint boxes missing on tracked tab:** verify `hold_horizon_results.json` exists. If not, run a Hold Horizon Analysis and watch terminal for `[HoldSweep] Results saved to hold_horizon_results.json`.
4. **HH analysis won't save:** look for `[HoldSweep] Could not save results: ...` in terminal — could be Defender CFA blocking writes.
5. **Tracked positions show wrong P&L:** confirm `entry_price` is set correctly per position; bot pulls fresh prices every 5 min but compares to entry_price for P&L %.
